# kagnet 写真视频提示词逻辑

## 一句话

写真视频提示词不是许愿“一段好看的美女动画”，而是写清一段影像为什么成立：先有一条真实发生的事件弧，再有一次有起幅落幅的镜头运动，然后是随时间稳定的妆造灯光场景，最后才是成像质感。这个技能有五个方向：生成一整套视频系列母版；生成同系列视频变体关键词链；生成单条详细控制型中文视频提示词；生成网页端大量抽卡用的短视频关键词；或根据一段短视频 / 一组参考图反向拆解可复用视频关键词。本 Skill 不绑定具体视频平台或模型；终端生成由宿主智能体按当前可用工具执行，所有输出都以可移植的中文拍摄指令与时长、比例、首尾帧等参数交付。

## 视频提示词生成原则

### 1. 时间先于构图：先动作弧，再运镜，再静止层

静态写真抓一拍，视频抓的是“一段变化”。写视频提示词前先回答三个时间问题：

1. **这一段时间里发生了什么**（事件弧：一个连续动作从发生推进到结果，例如风吹起发丝、雨滴落在脸颊、人物转身扶栏、镜头绕半圈后停在人物眼上）。
2. **镜头怎样动**（起幅：开始时镜头在哪；运动方式：推/拉/摇/移/升降/环绕/跟拍/手持/固定；落幅：结束时镜头停在什么画面）。
3. **静止元素怎样被时间穿过**（妆造、服装、场景、背景层级和光线在这段时间里如何保持稳定或有限变化）。

默认排序：

```text
事件弧 -> 镜头运动 -> 人物与表情响应 -> 妆造 / 服装 / 道具 -> 光线随时间演化 -> 场景 / 背景信息层级 -> 成像质感 -> 一致性防线
```

事件弧优先：没有事件、只要求“人物站着眨眨眼”的提示词最容易产生 AI 味。事件必须当前场景真实支持；不要为了活泼凭空增加不属于企划的事件。

### 2. 镜头运动写时间结构，不写“丝滑运镜”

“画面很丝滑”不是可执行信息。运镜必须写三件事：起幅镜头位置、运动方式与速度、落幅画面结果。示例：

- 从人物手部特写缓缓上摇到面部，镜头停在她抬眼看向镜头的一瞬，全程约 5 秒。
- 平缓地推近，从半身推到近景，焦点始终落在眼睛上，背景随推进自然压缩。
- 手持跟随人物从画面左侧走入景中，轻微晃动，停在人物侧身回望的瞬间。
- 环绕半圈，从侧前方绕到正侧，光源在背景中的位置随视角改变但人物受光保持真实。

写“运动速度”用自然语言（缓缓、平缓、快速后退、轻微手持抖动），不要只写“运镜感”。禁止与影像物理矛盾的组合：固定机位不能同时出现连续环绕推拉，除非明确写了多镜头剪接。

### 3. 人物事件与动作弧（表情因果的时间版）

身份素材回答“是谁”，表情与身体响应由当前事件驱动。每段视频先确定一个当前场景真实支持的具体事件，再编译“现场触发 → 身体即时反射 → 面部可见变化 → 视线与手部继续追随”的连续弧：

- 不只写“自然、灵动、微笑、发呆”；这些词没有说明表情为什么发生、如何随时间变化。
- 近景用眉眼、鼻翼、双颊、嘴唇和呼吸的小变化；全身或环境段还要让头肩、重心、手臂与步态响应同一事件。
- 动作、视线和表情若来自三个无关任务，即使每个局部都好看，也必须重构本段。
- 默认避开“身体背向镜头却扭头回看”的高风险动作，保持头肩方向自然。
- 一段视频通常是“一个动作从发生到结果”，不要要求一个 5 秒片段内完成三四个互不相关的转身换装；需要多动作时写成多镜头或明确的剪接结构。

### 4. 时间一致性：同一段、同一组的画面必须互相认识

视频最大的隐患是“每个瞬间都好看但连起来换脸、换装、换光”。编译时把一致性写成正向约束：

- 主要人物、妆发、服装、主导光线、主场景在本段内保持稳定；只允许事件驱动的有限变化（风吹动发丝、情绪带来的表情变化、光影随时间移动）。
- 跨段（同一企划分成多条短视频）时，写清“同一套企划、同一位置方向的主光、同一服装妆造系统”，让成组视频看起来像同一场拍摄。
- 只有当宿主平台的视频生成工具支持抽帧时，才在提示词中出现“首帧/尾帧稳定”“循环”“定格”等参数；不要把这些写成对具体平台的绑定，平台差异由宿主智能体对接。
- 人物身份素材只提供五官锚点，跨段保持一致的脸不靠“复制上一段的截图”，而是靠 Prompt 中明确写死的身份锚点与企划一致性；不为此增加逐帧对比验收层。

### 5. 光线写成“来源、落点、结果、以及如何随时间演化”

在静态的三段链上补时间：

```text
【光源】从【方向】进入，落在【皮肤 / 发丝 / 服装 / 道具】上，形成【高光 / 阴影 / 光斑】，在【哪段时间】里发生【什么有限变化】。
```

- 示例：机顶直闪在快门的整段时间内保持方向不变，人物进入光区时颊侧出现硬阴影，离开光区后影子自然拉长。
- 示例：午后窗光在 5 秒内明度几乎不变，只有纱帘被风吹动造成的柔和光斑在人物肩臂上缓慢游移。
- 机位一旦运动，光源、遮挡物与环境反射固定在世界空间中，不能“带着光源一起旋转”；先重建运动过程中的受光关系，再写本秒到下一秒看到的光照结果，不复制静态高光在二维画面的坐标。
- 阴天散射或柔和窗光不能无故变成狭窄硬边光、强轮廓光或舞台顶光；俯拍、仰拍、环绕只改变观看位置，不改变光源方位。

### 6. 皮肤纹理与皮肤反射分开写（加时间）

`真实皮肤微纹理`只控制毛孔、绒毛、细小纹理和肤色变化，不控制皮肤怎样反光。每条涉及人脸的视频 Prompt 还要根据景别和动作写皮肤反射，并说明反射是否随时间变化：

- 默认自然半哑光或克制缎光；T 区高光受控，脸颊以柔和漫反射为主；水润唇、玻璃唇、湿润眼妆只作用在对应五官区域，不扩散成额头、鼻翼和双颊的连续湿亮。
- 人物转头、低头、抬手挡光时，高光落点随脸部朝向移动，这是正常物理结果；但不要因此写“全脸反光”。
- 直闪或正午硬光 + 近景时，必须给出正向反射控制：额头与双颊保持柔和漫反射，T 区只有克制窄高光，水润质感只留在唇部；直闪随景别调整强度，不在脸上形成连续油膜。
- 只有炎热运动、刚跑完、雨水、泳池或用户明确水光肌时，才写汗光/湿亮，并限定发生区域与时间（例如发际线和鼻尖在跑动中渗出少量汗光）。

### 7. 妆造、服装、道具、场景：静态但可被时间穿过

- 穿搭只写服装本身（上衣/下装/外套/裙装/鞋袜/面料/颜色/版型/层次），饰品、眼镜、发饰、包、花、伞全放道具元素。
- 场景只写宏大环境、空间关系、季节、天气、时代气质；不重复具体道具。
- 道具元素列整组可用的道具池，用 `/` 分隔；单段只突出一个主道具，结尾必须写“（道具根据实际构图需求选取，不要将所有的道具全都塞进一个画面中）”。
- 衣服和头发要有“被时间穿过”的行为：风吹动裙摆、发丝飘起又落下、布料随动作起皱。这属于动作弧，不是单独的道具任务。
- 背景信息层级：先区分主体清晰区、主导大形、次级细节和低细节留白。视频里背景可以随焦点或镜头运动改变清晰度，但“某层背景是否清楚”要有原因，不能所有层同时高锐度高反差。

### 8. 变体、母版、抽卡、拆解都要带时间维度

同系列视频变体：固定层仍只保留“整体风格词链”与“成像机制 + 运动机制词链”，变量层可以重写人物、妆发、服装、场景、道具、镜头运动、事件弧、表情和现场光线。运动机制词链（例如“手持跟拍、轻微晃动、自然抓拍感”）属于固定层，但每段的具体起幅落幅、事件弧和光位随时间的变化属于本段变量。

系列视频母版：先定“企划的影像 DNA”（主题世界、共同妆照系统、共同运动语法、共同光线质感），再给每段 P 编号写独立事件弧与运镜任务，不能八段全部同一个机位同一套动作。

抽卡短视频关键词：保留比例、主成像方式、主运动方式、写真主题、人物妆造锚点、场景/道具池、事件弧池、轻量负面；放开具体动作、具体表情、具体子场景、运镜细节、是否循环。控制在 6–8 行，便于网页端批量。

视频拆解：除了静态层（妆造、服装、场景、光线、成像质感），还要拆“时间层”：事件弧是什么、镜头从哪到哪怎么动、动作速度、转场/剪接结构、前后一致性如何形成。

### 9. 不绑定平台：输出可移植参数，不必现平台名词

编译结果为任意视频平台可消费的中文指令，只做三件事：

- 用自然语言描述时间、动作、运镜与成像，不引用任何具体模型、API、提示词字段或厂商功能名。
- 参数（时长、比例、首帧、尾帧、循环、音效、字幕）写成人话；例如“时长约 5 秒、竖屏 9:16、片尾留一秒定格，不加字幕”而不是“resolution:… loop: true”。
- 假设宿主智能体会把这段指令翻译/适配到它选定的视频生成工具。本 Skill 不承诺任何平台的生成结果字段，也不在无工具环境声称已经出片。

## 视频提示词标准模块

每段最终 Prompt 是一段连续、紧凑的中文拍摄指令，按以下优先级组织，不显示内部模块标题：

1. 参考素材职责（若使用参考图/参考视频）。
2. 本段事件弧：持续发生的具体事件，从发生到结果。
3. 镜头运动：起幅、运动方式与速度、落幅；是否固定机位。
4. 人物身份或原创人物类型；身份与表情分控。
5. 妆容、发型、服装、饰品和主道具（随时间的行为）。
6. 场景、空间层次与背景信息层级。
7. 光线随时间演化：世界空间中的光源、遮挡、人物与环境落点、曝光关系在新机位下的连续性。
8. 成像机制：白平衡、色偏、反差、黑位、高光、锐度、微反差、噪点、压缩和景深；运动带来的模糊/晃动。
9. 可移植参数：时长、比例、首尾帧、循环/定格/音效（只在需要且平台支持时）。
10. 紧凑质量防线；只有用户明确要求时，才加入用户指定的署名文字。

## 四种视频输出模式

### 1. 视频系列母版

用于先规划一整套短视频企划、扩展系列骨架和固定格式输出。固定结构：

```text
【系列母版：主题名】

【比例】+【主成像与运动骨架】：比例 + 主视频质感 + 主运动方式 + 场景气质 + 系列情绪。

【五官/脸型】+【妆容】+【发型】

【穿搭】：服装池，不能写饰品。

【场景】：宏大环境和空间气质，不重复道具。

【道具元素】：道具池 / 饰品池 / 手持物 / 前景遮挡（道具根据实际构图需求选取，不要将所有的道具全都塞进一个画面中）

【镜头语言】：系列可变化的运镜池（推/拉/摇/移/环绕/手持/固定）。

【动作与事件弧】：
P01：具体画面任务。
P02：具体画面任务。
...
P08：具体画面任务。

【光线随时间演化】

【每段可移植参数】：时长 / 比例 / 循环 / 定格 / 音效。

【可以随机的变量】

【负面约束词】
```

P01-P08 默认 8 段；用户指定段数时按用户数量。每个 P 编号必须是一个可直接拍摄的视频画面任务（事件弧 + 运镜 + 落幅）。

### 2. 同系列视频变体关键词链

只固定整体风格词链与“成像机制 + 运动机制”词链，其他内容根据当前系列重新设计。每段在内部设计不同的观看关系和事件弧，再按标准模块顺序编译成一段无模块标题的连续中文关键词链；多段用 `P01 / P02 / ...` 区分。任意两段若在运镜方式、事件弧、表情、视线和落幅上大部分相同，就自动重构其中一段。

### 3. 详细视频提示词

用于精准控制单段画面。按“拍摄小抄”写：比例、主成像方式、事件弧、机位运动、人物妆造、服装、道具、场景、光线随时间演化、成像质感、可移植参数与负面约束。

### 4. 抽卡短视频关键词

用于网页端用同一审美骨架大量探索。保留风格 DNA 和事件弧池，放开动作细节、表情、子场景、运镜细节和是否循环；每行用逗号、顿号或 `/` 组织，6–8 行。

## 模式选择

- 默认：用户只说“给我视频 prompt / 分镜脚本”，输出详细视频提示词。
- 明确变体：说“变体 / 同系列视频变体”，输出同系列视频变体关键词链。
- 明确系列母版：说“系列母版 / 一套系列规划 / 固定格式”，输出视频系列母版。
- 明确抽卡：说“抽卡 / 网页端 / 大量生成 / 短关键词”，输出抽卡短视频关键词。
- 视频企划复拍：说“照这套拍视频 / 换个人拍一套视频 / 复刻这套企划”，读取 [视频企划复拍工作流](production-reshoot.md)。
- 图片/视频拆解后继续生成：根据用户目标选择详细版或抽卡版；未说明时只给拆解结果。

## 视频 / 组图拆解规则

拆解的目标是把可见影像翻译成能复用、能扩展、能直接进入视频生成提示词的视觉语言。

### 拆解两层法

1. 事实层：只承认可见信息。看不清的内容标为“疑似”，不补品牌、摄影师、器材、剪辑软件、帧率或图片外故事。
2. 时间层：静态图组只拆构图、光位、质感与人物事件；视频还要拆事件弧、运镜起落幅、动作速度、转场/剪接结构和前后一致性。

### 单段视频拆解

```text
【整体判断】：一句话说明这段视频的写真方向与主要成立点。

【固定锚点】：最应保留的 3-6 个视觉锚点。

【事件弧】：这一段时间发生了什么，从发生到结果。

【镜头运动】：起幅 / 运动方式与速度 / 落幅。

【时间一致性】：人物、妆发、服装、光线在片中如何保持一致。

【比例 + 成片质感 + 运动质感】：比例 + 成像方式 + 手持/固定/环绕等运动方式。

【妆容 + 发型 + 皮肤】：可见锚点，皮肤纹理与反射分开写。

【穿搭】【场景】【道具元素】：按静态写真规则压缩。

【光线随时间演化】：来源、方向、落点、结果以及有限变化。

【可移植参数】：估计时长、比例、是否需要循环或其他产出参数。

【可以随机的变量】【不建议固定的偶发元素】：分时间层与静态层。
```

### 组图 / 组片段拆解

先看“重复出现的视觉机制与运动机制”，不要先逐张罗列。先输出整体判断、系列共同视觉 DNA（含共同运动语法）、系列变量池、单段差异弧；再按上述模块整理整组可复用关键词。多张稳定出现的内容进入共同 DNA 或固定锚点；每段不同的运镜、事件、表情、景别进入差异变量池；只出现一次且不影响系列识别的细节进入不建议固定的偶发元素。

用户要求继续生成完整视频提示词时，再把拆解结果转成最终提示词；没有明确要求时，只输出拆解结果。

## 详细视频提示词模板

```text
【比例】+【事件弧】+【镜头运动】
【画幅比例】 + 【约X秒】 + 【从哪起幅、怎样运动、停在什么画面】 + 【持续发生的事件（发生—推进—结果）】
```
